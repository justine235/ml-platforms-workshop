# MLflow concept map: open-source MLflow vs Microsoft Fabric vs Azure Machine Learning

This file is the presenter's reference for Part 1. It keeps the comparison grounded in the same MLflow vocabulary the audience already knows from open-source MLflow or Databricks, then makes the platform differences explicit.

## Core concept map

| Concept | Open-source MLflow | Microsoft Fabric | Azure Machine Learning | Sources |
|---|---|---|---|---|
| Tracking server / URI | You point the client at a backend with `mlflow.set_tracking_uri(...)`. | Fabric notebooks preconfigure tracking and auth for the current workspace; cross-workspace logging uses `sds://api.fabric.microsoft.com/v1/workspaces/<workspace-id>/mlflow`. | AML workspaces expose an `mlflow_tracking_uri`; AML jobs configure tracking automatically, external clients set the URI explicitly. | OSS: https://mlflow.org/docs/latest/ml/tracking/  Fabric: https://learn.microsoft.com/en-us/fabric/data-science/machine-learning-cross-workspace-logging  AML: https://learn.microsoft.com/en-us/azure/machine-learning/how-to-use-mlflow-configure-tracking?view=azureml-api-2 |
| Experiment | Standard container for runs. | First-class **Experiment** item in the workspace UI. | Standard MLflow experiment concept backed by the AML workspace tracking server. | OSS: https://mlflow.org/docs/latest/ml/tracking/  Fabric: https://learn.microsoft.com/en-us/fabric/data-science/machine-learning-experiment  AML: https://learn.microsoft.com/en-us/azure/machine-learning/how-to-use-mlflow-configure-tracking?view=azureml-api-2 |
| Run | `mlflow.start_run()` logs params, metrics, tags, artifacts, and models. | Same MLflow run semantics; run comparison is built into the Experiment item. | Same MLflow run semantics; AML stores them in the workspace tracking server. | OSS: https://mlflow.org/docs/latest/ml/tracking/tracking-api/  Fabric: https://learn.microsoft.com/en-us/fabric/data-science/machine-learning-experiment  AML: https://learn.microsoft.com/en-us/azure/machine-learning/how-to-use-mlflow-configure-tracking?view=azureml-api-2 |

| Params / metrics / tags / artifacts | Core tracking primitives. | Fully supported; Experiment item exposes them directly. Run tags have documented limits and reserved prefixes. | Fully supported. AML-specific hard caps for run items were not verified here. | OSS: https://mlflow.org/docs/latest/ml/tracking/  Fabric: https://learn.microsoft.com/en-us/fabric/data-science/machine-learning-experiment  AML: https://learn.microsoft.com/en-us/azure/machine-learning/how-to-use-mlflow-configure-tracking?view=azureml-api-2 |
| Autologging | Opt-in via `mlflow.autolog()`. | On by default in Fabric Data Science notebooks; admins can disable it; use `exclusive=False` if you also want manual logging. | Supported, but you call it explicitly. | OSS: https://mlflow.org/docs/latest/ml/tracking/autolog/  Fabric: https://learn.microsoft.com/en-us/fabric/data-science/mlflow-autologging  AML: https://learn.microsoft.com/en-us/azure/machine-learning/how-to-log-mlflow-models?view=azureml-api-2 |
| Model flavors | Standard MLflow flavors (`sklearn`, `xgboost`, `pyfunc`, and so on). | Same MLflow flavor model. AML docs focus on deployable MLflow-format models rather than publishing one single flavor matrix. | OSS: https://mlflow.org/docs/latest/ml/model-registry/  Fabric: https://learn.microsoft.com/en-us/fabric/data-science/mlflow-autologging ; https://learn.microsoft.com/en-us/fabric/data-science/model-scoring-predict ; https://learn.microsoft.com/en-us/fabric/data-science/model-endpoints  AML: https://learn.microsoft.com/en-us/azure/machine-learning/how-to-log-mlflow-models?view=azureml-api-2 |
| Signature and input example | Strongly recommended model contract. | Effectively required for the nice scoring paths: `PREDICT` and model endpoints depend on a valid schema/signature. | Strongly recommended; improves no-code deploy contract and Swagger generation. | OSS: https://mlflow.org/docs/latest/ml/model/signatures/  Fabric: https://learn.microsoft.com/en-us/fabric/data-science/model-scoring-predict ; https://learn.microsoft.com/en-us/fabric/data-science/model-endpoints  AML: https://learn.microsoft.com/en-us/azure/machine-learning/how-to-log-mlflow-models?view=azureml-api-2 |

| Model version | Standard immutable versioned artifact. | The documented Fabric registry story is version-centric. | Standard AML model version concept. | OSS: https://mlflow.org/docs/latest/ml/model-registry/  Fabric: https://learn.microsoft.com/en-us/fabric/data-science/machine-learning-model  AML: https://learn.microsoft.com/en-us/azure/machine-learning/how-to-manage-models-mlflow?view=azureml-api-2 |

| Model alias | Native OSS registry feature. | Fabric alias support is `⚠ UNVERIFIED / not a documented Fabric-first pattern`. | AML alias support is `⚠ UNVERIFIED`; current AML docs do not make it a safe workshop dependency. | OSS: https://mlflow.org/docs/latest/ml/model-registry/  Fabric: `⚠ UNVERIFIED`  AML: `⚠ UNVERIFIED` |
| Model tags | Supported on registered models and versions. | Supported through version metadata and ML model item surfaces. | Model version tags are documented and supported. | OSS: https://mlflow.org/docs/latest/ml/model-registry/  Fabric: https://learn.microsoft.com/en-us/fabric/data-science/machine-learning-model  AML: https://learn.microsoft.com/en-us/azure/machine-learning/how-to-manage-models-mlflow?view=azureml-api-2 |
| `pyfunc` loading | Standard portability layer for Python inference. | Same `pyfunc` model concept applies, but Fabric's first-class scoring features still follow Fabric-specific rules around signatures and supported paths. | Explicitly documented as the escape hatch for custom inference behavior. | OSS: https://mlflow.org/docs/latest/api_reference/python_api/mlflow.pyfunc.html  Fabric: https://learn.microsoft.com/en-us/fabric/data-science/model-scoring-predict  AML: https://learn.microsoft.com/en-us/azure/machine-learning/how-to-log-mlflow-models?view=azureml-api-2 |
| Registry loading (`models:/`) | Standard registry URI scheme. | Load versions with `models:/<name>/<version>`. | Load models with `models:/<name>/latest`, `models:/<name>/<version>`, or `models:/<name>/<stage>`; stage loading exists even though stage-based deployment is unsupported. | OSS: https://mlflow.org/docs/latest/ml/model-registry/  Fabric: https://learn.microsoft.com/en-us/fabric/data-science/machine-learning-model  AML: https://learn.microsoft.com/en-us/azure/machine-learning/how-to-manage-models-mlflow?view=azureml-api-2 |
| Manual model logging API | MLflow 2.x uses `artifact_path="model"`; MLflow 3 documents `name="model"` and LoggedModel semantics. | Fabric supports MLflow 3 up to 3.1 with explicit install; default notebooks still ship MLflow 2.x. | AML is pinned to MLflow 2.16.x or earlier, so use the MLflow 2.x `artifact_path` pattern in AML-safe code. | OSS: https://mlflow.org/docs/latest/ml/model-registry/  Fabric: https://learn.microsoft.com/en-us/fabric/data-science/mlflow-3-overview  AML: https://learn.microsoft.com/en-us/azure/machine-learning/how-to-log-mlflow-models?view=azureml-api-2 |
| Batch scoring | No first-class managed batch platform in core MLflow itself; you build it around the model artifact. | Fabric supports `PREDICT`, generated scoring notebooks, and SynapseML `MLFlowTransformer`. | AML batch endpoints support MLflow models with a no-code path. | OSS: `⚠ UNVERIFIED` as a core MLflow product feature  Fabric: https://learn.microsoft.com/en-us/fabric/data-science/model-scoring-predict  AML: https://learn.microsoft.com/en-us/azure/machine-learning/how-to-mlflow-batch?view=azureml-api-2 |
| Real-time serving | Core MLflow is not a managed serving platform by itself. | Fabric **ML model endpoints** exist, but are `⚠ PREVIEW`. | AML managed online endpoints support MLflow-model deployment without a scoring script. | OSS: `⚠ UNVERIFIED` as a core MLflow managed service feature  Fabric: https://learn.microsoft.com/en-us/fabric/data-science/model-endpoints  AML: https://learn.microsoft.com/en-us/azure/machine-learning/how-to-deploy-mlflow-models-online-endpoints?view=azureml-api-2 |

## Top 10 differences that bite you, and the fix

1. **Fabric can do MLflow 3 LoggedModels and tracing; AML cannot.**  
   **Fix:** keep the shared demo on classic model artifacts and show tracing as a Fabric-only extension.  
   **Sources:** https://learn.microsoft.com/en-us/fabric/data-science/mlflow-3-overview ; https://learn.microsoft.com/en-us/azure/machine-learning/how-to-log-mlflow-models?view=azureml-api-2

2. **AML is pinned to `mlflow<=2.16.2`, while current Fabric runtime ships 2.22.0.**  
   **Fix:** pin per-platform environments and code to the lowest common contract.  
   **Sources:** https://github.com/microsoft/synapse-spark-runtime ; https://learn.microsoft.com/en-us/azure/machine-learning/how-to-log-mlflow-models?view=azureml-api-2

3. **Fabric autologs by default; OSS and AML usually do not.**  
   **Fix:** call `mlflow.autolog(...)` explicitly in code when you want deterministic behavior, then disable or override it intentionally.  
   **Sources:** https://learn.microsoft.com/en-us/fabric/data-science/mlflow-autologging ; https://mlflow.org/docs/latest/ml/tracking/autolog/

4. **Fabric scoring paths require a signature; AML strongly benefits from one.**  
   **Fix:** always log `signature` and `input_example`.  
   **Sources:** https://learn.microsoft.com/en-us/fabric/data-science/model-scoring-predict ; https://learn.microsoft.com/en-us/fabric/data-science/model-endpoints ; https://learn.microsoft.com/en-us/azure/machine-learning/how-to-log-mlflow-models?view=azureml-api-2

5. **Fabric model items are version-first, not stage-first.**  
   **Fix:** teach explicit versions and tags, not Fabric stage promotion.  
   **Source:** https://learn.microsoft.com/en-us/fabric/data-science/machine-learning-model

6. **AML stages exist, but only through the MLflow SDK and not as a deploy primitive.**  
   **Fix:** deploy a concrete model version, not `models:/name/Staging`.  
   **Source:** https://learn.microsoft.com/en-us/azure/machine-learning/how-to-manage-models-mlflow?view=azureml-api-2

7. **Git/deployment pipelines do not move Fabric ML model binaries or run history.**  
   **Fix:** promote by re-log / re-register or retrain in the target workspace.  
   **Sources:** https://learn.microsoft.com/en-us/fabric/data-science/machine-learning-artifacts-git-deployment-pipelines ; https://learn.microsoft.com/en-us/fabric/data-science/machine-learning-cross-workspace-logging

8. **AML registry operations are workspace-local.**  
   **Fix:** use AML registries or SDK asset promotion for multi-workspace flows, or export/import the MLflow model folder deliberately.  
   **Source:** https://learn.microsoft.com/en-us/azure/machine-learning/how-to-manage-models-mlflow?view=azureml-api-2

9. **Fabric endpoints are preview; AML online endpoints are the production-oriented managed serving path.**  
   **Fix:** present Fabric endpoints honestly as a preview and AML endpoints as the managed serving reference.  
   **Sources:** https://learn.microsoft.com/en-us/fabric/data-science/model-endpoints ; https://learn.microsoft.com/en-us/azure/machine-learning/how-to-deploy-mlflow-models-online-endpoints?view=azureml-api-2

10. **Aliases are unsafe as a cross-platform teaching primitive.**  
   **Fix:** standardize on immutable model version numbers plus tags in the live demo.  
   **Sources:** https://mlflow.org/docs/latest/ml/model-registry/ ; https://learn.microsoft.com/en-us/fabric/data-science/machine-learning-model ; https://learn.microsoft.com/en-us/azure/machine-learning/how-to-manage-models-mlflow?view=azureml-api-2

## Presenter summary

- **What is identical:** experiment, run, params, metrics, tags, artifacts, autologging concept, model flavors, signature/input example, `runs:/...` and `models:/...` URIs, `pyfunc`, and the ability to move the same MLflow model folder between platforms.
- **What differs:** runtime pinning, default autologging behavior, registry semantics, serving surfaces, tracking URI formats, artifact promotion patterns, and MLflow 3 support.
- **The safest cross-platform line:** "Fabric and Azure ML both speak real MLflow. The model artifact is portable. The operational wrappers are not identical."

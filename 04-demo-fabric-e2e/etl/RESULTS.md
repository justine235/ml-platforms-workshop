  `out_of_range_values_nulled` expected 217, got 219. Root cause: the script

  `nb_02_silver_clean_resolve` later removes as duplicates on `event_id`), while the
  ground truth / notebook value is computed *after* that dedup. Two of the removed
  duplicate rows happened to also carry an out-of-range sensor value, hence 219 vs
  217. This was a bug in the comparison harness, not in the ETL notebook. Fixed the
  script to replicate the notebook's exact `Window.partitionBy("event_id").orderBy(
  ingest_epoch, _source_file)` dedup before counting spikes.
- Second execution (after the fix), run again one at a time (~2 min, same
  Delta tables, no notebook rerun): **29/29 metrics OK, `all_ok: true`.**

## Portability pass (this run)
- Goal: make the kit standalone (the presenter only has the workshop
  folder - no scratch, venv or parent folder assumed) and fix a real latent
  Fabric crash. No ETL logic or number was changed in this pass.
- Fixed bug: `nb_00_setup.py` and `nb_01_bronze_ingest.py` computed
  `WORKSHOP_ROOT = ETL_ROOT.parents[2]` unconditionally. In Fabric, `__file__`
  is undefined so `ETL_ROOT = Path.cwd()`; a shallow cwd makes `.parents[2]`
  raise `IndexError` on the very first notebook run. Removed `WORKSHOP_ROOT`
  and the old scratch default entirely; local-only raw-data path resolution now
  runs only `if not raw_root and not IS_FABRIC`, using `FLEET_RAW_ROOT` env var
  or `ETL_ROOT.parents[1] / "02-demo-data" / "data"` (kit-relative, computed
  only from a real `__file__`-based path, never touched when `IS_FABRIC`).
- Fixed bug: `IS_FABRIC = "notebookutils" in globals()` in all four notebooks
  does not find the Fabric-injected `notebookutils` object, since it is exposed
  as a builtin, not a module global. Replaced with
  `try: notebookutils; IS_FABRIC = True` / `except NameError: IS_FABRIC = False`
  in all four notebooks.
- `local-validation\run_local.py` and `compare_ground_truth.py` no longer
  hardcode the workshop folder name or any virtual-environment path. Kit root is derived as
  `ETL_ROOT.parents[1]`; data/truth default to `<kit>\02-demo-data\data` /
  `...\truth`, overridable via `FLEET_RAW_ROOT` / `FLEET_TRUTH_ROOT`. JDK/Hadoop
  come from `JAVA_HOME` / `HADOOP_HOME` env vars (their `bin\` prepended to
  PATH); a missing `JAVA_HOME` now raises one clear error naming JDK 17,
  `JAVA_HOME`, and (on Windows) `HADOOP_HOME` + `winutils.exe`/`hadoop.dll`.
  `compare_ground_truth.py` now writes only to `local-validation\results\`
  (the root-level duplicate copies were deleted).
- Docs updated to neutral wording: `rebuild-guide.md` Option B now reads
  `cd 02-demo-data; python fleet_data_generator.py --out data --truth-dir truth
  --with-drift` (plus a mention of the env-var overrides); `RESULTS.md` no
  longer names any local scratch or virtual-environment path (versions, timings,
  and the 29/29 result are unchanged).
- Notebooks and Fabric Git sources regenerated from `notebooks-src\*.py` via
  `tools\build_notebooks.py`; re-validated with `py_compile`, `nbformat`, and
  JSON parsing - all clean, and confirmed no scratch-folder default,
  `WORKSHOP_ROOT`, `parents[2]` or old `IS_FABRIC` pattern remains anywhere in `notebooks\` or
  `fabric-git\`.
- Re-ran the full local pipeline (`run_local.py` then `compare_ground_truth.py`)
  one at a time with `FLEET_RAW_ROOT`/`FLEET_TRUTH_ROOT`/`JAVA_HOME`/

  nb_00 no longer uses it: the Fabric branch checks each file with
  `notebookutils.fs.exists("Files/raw/<file>")`, reads `_manifest.json` through

- **Left, correct** - `notebookutils.notebook.exit(json.dumps(...))` in all

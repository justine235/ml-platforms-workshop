# Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| `Missing required raw files` in `nb_00_setup` | `Files/raw` is empty, incomplete, or the wrong lakehouse is attached | Reattach `lh_fleet` as default lakehouse, restart the session, and verify all 12 required files exist under `Files/raw`. |
| `Could not list Files/raw in the attached lakehouse ...` (RuntimeError from `nb_00_setup`) | The raw files were uploaded a moment ago and the file listing has not caught up (Learn documents a default 120-second file cache for the default lakehouse mount; ⚠ UNVERIFIED that it is the cause here), or no default lakehouse is attached | Wait about 2 minutes and re-run the cell. If it persists, confirm `lh_fleet` is the default lakehouse, the session was restarted, and `raw/` sits directly under `Files/`. |
| `nb_00_setup` or `nb_01_bronze_ingest` fails with a path-not-found or table-not-found error (⚠ UNVERIFIED exact text) | `lh_fleet` is not the DEFAULT lakehouse of the notebook, or the session was not restarted after attaching it | Add `lh_fleet` with **Add lakehouse**, pin it as default, stop and restart the session, run again. Relative `Files/...` / `Tables/...` paths, `CREATE SCHEMA` and `saveAsTable("bronze.x")` all act on the default lakehouse. |
| `CREATE SCHEMA` fails, or `bronze` / `silver` / `gold` / `ml` do not appear (⚠ UNVERIFIED exact text) | No default lakehouse, or `lh_fleet` was created without **Lakehouse schemas** | Recreate `lh_fleet` with **Lakehouse schemas** checked, attach it as default, restart the session, re-run `nb_00_setup` (it uses `CREATE SCHEMA IF NOT EXISTS` and is safe to re-run). |
| Results or SQL errors differ from the rehearsal (casts, nulls, errors on malformed values) | The workspace runs a different runtime: a new workspace may default to Runtime 2.0 (Spark 4.1), which was not rehearsed with these notebooks | Run `print(spark.version)`; if it is not `3.5.x`, pin Runtime 1.3 (`rebuild-guide.md` section 3) and restart the session. Only the ANSI setting was tried locally (Spark 3.5.6, no error, same tables); anything else about Spark 4.1 is ⚠ UNVERIFIED for this kit. |
| Notebook reads or writes the wrong location | Relative `Files/...` or `Tables/...` path used without the correct default lakehouse | Reattach the notebook to `lh_fleet` and restart the session; for cross-lakehouse access use ABFSS paths. |
| Tables land in `dbo` instead of `bronze` / `silver` / `gold` | Save path omitted the schema name | Use `saveAsTable("schema.table")` everywhere. |
| `silver.telemetry` count is not 207,691 | Dedupe or timestamp parsing logic changed | Recheck `event_id` dedupe, epoch-ms conversion, and that only the base-window telematics (nb_01 `telematics/*.jsonl`) feed this table; the optional October batch goes through the same shared silver function but writes to a separate `silver.telemetry_drift` table, so it cannot inflate or shrink this count. |
| Telematics resolution counts drift | Asset normalization regex or serial normalization changed | Recheck the exact regex and the `EXACT_NORM → SERIAL → CROSSWALK → UNRESOLVED` order. |
| CMMS resolution or time-anomaly counts drift | Site time zone join or wall-clock parsing failed | Verify `site_master.timezone`, `to_utc_timestamp`, and the swap of `closed < opened`. |
| Gold tables look missing in the SQL view right after the Spark write | SQL analytics endpoint metadata sync lag | Stay in the notebook or Lakehouse Spark view; refresh later before any SQL-only demo step. |
| Bronze or silver run is slower than expected | Cold Spark session or undersized capacity | Start the workspace early, warm one notebook before the audience arrives, and avoid parallel heavy jobs. |
| Pipeline Notebook activity starts slowly | Spark session cold start | Accept the first-run delay, or pre-run one notebook in rehearsal. Optional session tags require the workspace high-concurrency setting. |
| Pipeline Notebook activity cannot see notebook parameters | Parameter cell not tagged or base parameters not refreshed | Reopen the notebook, confirm the parameter cell, then reselect the notebook in the activity and repopulate base parameters. |
| Gold run surfaces too many or too few unmatched episodes | Match window or significance rule changed | Recheck `CRIT or WARN with n_records >= 3`, and the `[-24 h, +7 d]` work-order window. |
| Preview pane shows old counts | Cached preview or lagging metadata | Refresh the preview, reopen the table, or show notebook output instead. |
| Schema evolution fails on `coolant_level_pct` | Write path dropped the additive column or schema settings differ | Keep the telematics bronze schema explicit and preserve `coolant_level_pct`; in Delta mode use overwrite with schema-aware settings. |
| Notebook session times out during a live rerun | Inactive browser session or capacity pressure | Reopen the notebook, rerun only the current step, and use pre-run outputs as fallback. |
| Notebooks imported from `.ipynb` or synced from Git show no lakehouse in the Explorer pane | Imports and Git syncs do not carry a lakehouse binding into a new workspace (the shipped notebooks have an empty `dependencies` block in their metadata) | Open each notebook, **Add lakehouse** → existing `lh_fleet`, pin it as default, restart the session. Do it for every notebook before the first run. |
| Workspace user can open the notebook but cannot run or save | Missing workspace role | Grant Contributor or higher in the workspace. |
| `silver.telemetry_drift` missing or 0 rows | `02-demo-data/data/telematics_drift/` not generated, or nb_01 could not read it | Optional table: only appears when the rehearsal data was generated with `--with-drift`. Re-generate with that flag, or skip - nb_07 `RunDriftMonitor` needs it but nb_00-nb_03 never fail without it. |
